# e2e — браузерные проверки продукта

Playwright гоняет реальные сценарии в браузере против **уже запущенного**
продукта. Это следующий шаг после дымового теста
([scripts/smoke-test.sh](../scripts/smoke-test.sh)): тот проверяет API одним
`curl`, здесь — те же сценарии глазами пользователя, кликами по интерфейсу.

Селекторы висят на атрибутах `data-qa` (их требует
[CLAUDE.md](../CLAUDE.md) для всей вёрстки), поэтому тесты не ломаются от
перевёрстки и не зависят от языка интерфейса. В конфиге
`testIdAttribute: 'data-qa'`, так что `getByTestId('login-page')` ищет
`[data-qa="login-page"]`.

## Что проверяется

| Файл                                             | Сценарий                                                       |
| ------------------------------------------------ | ------------------------------------------------------------- |
| [auth.spec.ts](tests/auth.spec.ts)               | Регистрация → кабинет → выход → вход; отказ без токена и с неверным паролем |
| [employees.spec.ts](tests/employees.spec.ts)     | Заведение, смена роли, отключение (и запрет входа), удаление; наблюдатель не видит управление |
| [profile.spec.ts](tests/profile.spec.ts)         | Сохранение «о себе»; смена пароля и вход по новому             |
| [org-settings.spec.ts](tests/org-settings.spec.ts) | Изменение названия компании                                   |

## Как запустить

Тесты НЕ поднимают приложение — оно должно быть доступно по `BASE_URL`.

```bash
# Установка (один раз): зависимости и браузер.
npm --prefix e2e ci
npm --prefix e2e run install-browsers

# Против собранного образа (как в CI) — предварительно `make up`.
BASE_URL=http://localhost:8000 npm --prefix e2e test

# Против серверов разработки (make dev-api + make dev-web).
BASE_URL=http://localhost:5173 npm --prefix e2e test
```

По умолчанию `BASE_URL` — `http://localhost:8000`, тот же адрес, что у `make up`
и дымового теста.

Отчёт после прогона: `npm --prefix e2e run report`.

## Где это в CI

Тесты встают на те же ворота, что и дымовой тест, — в
[build.yml](../.github/workflows/build.yml), против собранного образа **до** его
публикации. Провал означает, что образ в registry не попадёт. Порядок внутри
job'а: сеть → БД → миграции → приложение → дымовой тест → e2e → публикация.

Видео каждого сценария (`video: 'on'`) и HTML-отчёт выкладываются артефактом
`playwright-videos-<номер прогона>` со сроком жизни **1 день**. Учтите: артефакт
GitHub — это zip на скачивание, инлайнового проигрывания в интерфейсе GitHub
нет. Скачали → `.webm` открываются в браузере, отчёт — своим `index.html`.
Чтобы не копить видео зелёных прогонов, поменяйте `video` на `retain-on-failure`
в [playwright.config.ts](playwright.config.ts).
