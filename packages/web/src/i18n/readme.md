# Интернационализация фронтенда

i18next + react-i18next. Языки: русский и английский.

## ⚠️ Два флага, без которых всё молча ломается

```ts
keySeparator: false,
nsSeparator: false,
```

По умолчанию i18next читает точку как разделитель вложенности, а двоеточие — как
namespace. Наши ключи плоские и dot-namespaced (`'auth.login.title'`), поэтому с
включёнными разделителями i18next искал бы вложенный объект `auth → login →
title`, не находил его и **молча возвращал бы саму строку ключа**.

Симптом: в интерфейсе вместо текста видны ключи (`auth.login.title`). Ошибок при
этом нет нигде — ни в консоли, ни в сборке. Это самая вероятная тихая поломка в
этом стеке, поэтому оба флага трогать нельзя.

## Плоские ключи целиком

Ключ пишется одной строкой-литералом:

```ts
t('auth.login.title');          // да
t(`auth.${page}.title`);        // нет
```

Собранный из фрагментов ключ невозможно найти грепом, и его теряют при
рефакторинге — правило общее для бэкенда и фронтенда.

## Согласованность локалей проверяет компилятор

`en-US.ts` — эталон. `ru-RU.ts` типизирован как `typeof enUS`:

```ts
import type enUS from './en-US';

const ruRU: typeof enUS = { ... };
```

Пропущенный или лишний ключ — **ошибка компиляции**. Отдельный тест на
согласованность локалей не нужен: это делает `tsc`. (На бэкенде аналогичную роль
играет `tests/unit/test_i18n.py` — там такого трюка с типами нет.)

Именно поэтому локали — это `.ts` модули, а не JSON.

## Два формата кода языка

Бэкенд оперирует ISO 639-1 (`ru`), фронтенд — полными тегами (`ru-RU`), потому
что их требует AntD. Стык в одном месте — `index.ts`:

- `toAppLocale('ru')` → `'ru-RU'`
- `toBackendLocale('ru-RU')` → `'ru'`

Больше нигде конвертировать не нужно.

## Что где переводится

| Что                       | Кто переводит | Почему                                              |
| ------------------------- | ------------- | --------------------------------------------------- |
| Интерфейс                 | Фронтенд      | Тексты статичны и известны на сборке                 |
| Сообщения об ошибках API  | Бэкенд        | Только он знает, какая именно ошибка произошла       |

Бэкенд берёт язык из профиля пользователя, а для неаутентифицированных — из
заголовка `Accept-Language`. Поэтому при смене языка интерфейса выбор
сохраняется в localStorage **и** уходит в профиль — иначе ошибки сервера
приходили бы на прежнем языке.

## AntD

Свои локали AntD (пагинация, календари) подключаются в `App.tsx` через
`ConfigProvider locale=...`. Это отдельно от наших переводов и обязательно:
без этого кнопки самого AntD останутся английскими.

## Добавление языка

1. Создать `locales/<tag>.ts`, типизировать как `typeof enUS` — компилятор
   покажет все недостающие ключи.
2. Добавить тег в `SUPPORTED_LOCALES` и в `resources` в `index.ts`.
3. Добавить локаль AntD в `ANTD_LOCALES` в `App.tsx`.
4. Добавить подпись в `LOCALE_LABELS` в `components/LangSwitch.tsx`.
5. На бэкенде: создать `i18n/<код>.py` и добавить его в `MESSAGES` и `Locale`.
