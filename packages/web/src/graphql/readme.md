# GraphQL на фронтенде

## Цепочка кодогенерации

Главный механизм безопасности рефакторинга в проекте:

```
Python-резолверы  →  make schema  →  packages/api/schema.graphql
                                             ↓
                                     npm run codegen
                                             ↓
              src/graphql/generated/  (в .gitignore)
```

`codegen.ts` читает **SDL-файл**, а не запущенный сервер: генерация должна
работать в CI и в Docker-сборке, где поднять бэкенд с базой негде.

Запросы пишутся прямо в компонентах через `gql` из `@/graphql/generated` —
отдельные `.graphql` файлы не нужны. Все шаблоны валидируются против схемы.

**Что это даёт.** Переименовали поле на бэкенде и забыли поправить фронтенд —
`npm run codegen` падает с указанием файла и строки:

```
Cannot query field "bio" on type "User". Did you mean "id"?
  at src/hooks/useCurrentUser.ts:7:7
```

В Docker-сборке стейдж `web-builder` выполняет codegen до `vite build`, поэтому
битый образ физически не соберётся и не попадёт в registry.

**Важно:** `gql` импортируется из `@/graphql/generated`, а НЕ из `@apollo/client`.
Только первый возвращает `TypedDocumentNode` — с ним `useQuery`/`useMutation`
типизируются автоматически. Импорт из `@apollo/client` тихо отключит типизацию.

### После изменения схемы

```bash
make codegen   # = make schema + npm run codegen
```

`schema.graphql` коммитится (в отличие от прототипа): это контракт API, его diff
виден при ревью, а CI ловит «поменял резолвер, но не перегенерировал».
`src/graphql/generated/` — наоборот, в `.gitignore`: артефакт сборки.

## Enum прав приезжает сам

`UserPermissions` не копируется и не дублируется — он объявлен в
`services/permissions.py` на бэкенде, попадает в схему и генерируется в
`generated/graphql.ts` как настоящий TypeScript-enum.

В `codegen.ts` стоит `namingConvention: { enumValues: 'keep' }`: без него
codegen переименовал бы `Permission_users_see` → `PermissionUsersSee`, и одно и
то же право звалось бы по-разному в двух языках. С ним имена буквально
совпадают, и право находится грепом по всему репозиторию.

Рассинхрон невозможен: удалите право в Python — codegen упадёт на фронтенде.

## Клиент

`client.ts` — три звена, порядок важен: `errorLink` → `authLink` → `httpLink`.
Поставьте `errorLink` после `authLink` — он перестанет видеть ошибки.

- **httpLink** — относительный `/api/v1/graphql`. Бэкенд сам раздаёт SPA,
  поэтому запрос идёт с того же origin и CORS не нужен. В разработке тот же
  путь проксирует Vite (см. `vite.config.ts`).
- **authLink** — подставляет `Bearer` и запоминает в контексте запроса, с каким
  токеном тот ушёл.
- **errorLink** — при `UNAUTHENTICATED` чистит токен и уводит на `/login`.
  Логирует каждую ошибку: пустых `catch` в проекте не бывает.

### Гонка токенов в errorLink

`authLink` кладёт `requestedWithToken` в контекст не просто так. Если за время
полёта запроса токен успели заменить (вошли заново в соседней вкладке), ошибка
`UNAUTHENTICATED` относится к УЖЕ устаревшему запросу — разлогинивать по ней
нельзя, это стёрло бы только что полученный рабочий токен. Поэтому перед
разлогином сверяем токен запроса с текущим.

Операции `Login` и `Register` исключены из разлогинивания: они показывают
ошибку в форме сами.

## Контракт ошибок

Задан бэкендом (`graphql/errors.py`), разбирается в `@/utils/graphqlError.ts`:

| Поле                | Смысл                                                     |
| ------------------- | --------------------------------------------------------- |
| `message`           | Уже локализовано бэкендом по `Accept-Language`             |
| `extensions.code`   | `BAD_USER_INPUT`, `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND` |
| `extensions.field`  | Имя поля формы, если ошибка относится к конкретному инпуту |

Сообщения не переводятся на фронтенде: их переводит бэкенд, потому что он же
знает, какая именно ошибка произошла. Локаль он берёт из профиля пользователя
или из `Accept-Language`.
