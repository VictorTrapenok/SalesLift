## ⚠️ Расхождения между README и реальностью

README — страница продукта и описывает целевое состояние. Ниже то, где оно ещё
не достигнуто. Список обязан сокращаться, а не расти.

| Заявлено в README                       | Как на самом деле                                                                                                       |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `make up` тянет образ из ghcr.io        | CI настроен и опубликует образ, но пока не выпущен ни один тег — в registry пусто, и compose соберёт образ локально.      |
| Развёртывание Helm-чартом               | Чарта пока нет, команда из README не сработает.                                                                          |
| Загрузка и анализ звонков               | Домена звонков нет вовсе. Есть платформа, на которую он ляжет.                                                           |

**Чтобы закрыть первую строку**, достаточно выпустить тег — см.
[.github/ci.md](.github/ci.md):

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Сборку образа не удалось проверить локально: в среде разработки реестр npm
недоступен изнутри контейнера (`ETIMEDOUT`), а сборщик Docker'а падает на
дефекте buildkit. Проверится в CI, где сборка идёт на чистой машине.
Дымовой тест, который решает судьбу образа, локально прогнан и проходит.

## Готово

Всё перечисленное покрыто тестами и проверено запуском.

### Компании и сотрудники

- [x] Регистрация компании. Первый зарегистрировавшийся становится администратором.
- [x] Вход по e-mail и паролю. Компания определяется по e-mail — поля «компания»
      в форме нет ([почему](docs/adr/0001-tenant-resolution.md)).
- [x] Роли: администратор, менеджер, наблюдатель.
- [x] Мультитенантность: каждый запрос к данным скоупится компанией явно.
- [x] Управление сотрудниками: заведение (администратор задаёт пароль сам,
      приглашений по ссылке пока нет), смена роли, отключение/включение и
      удаление. Действие над собой запрещено — на этом же держится инвариант
      «последнего администратора не разжаловать и не удалить».
- [x] Настройки компании: название и реквизиты. Смотрит менеджер, меняет
      администратор.
- [x] Профиль: имя, «о себе», смена пароля с проверкой текущего.

Оговорка по последним трём разделам: интеграционные тесты на них написаны, но
локально не прогнаны — в среде разработки нет доступа к Docker, а тестовая
PostgreSQL поднимается контейнером. Юнит-тесты, линтеры, `mypy --strict`,
`tsc` и сборка фронтенда зелёные. Первый прогон интеграционных — в CI.

### Платформа

- [x] GraphQL API со строгой типизацией и локализованными ошибками.
- [x] Схема БД, миграции, мягкое удаление.
- [x] Интерфейс: вход, регистрация, каркас кабинета, ru/en.
- [x] Кодогенерация типов фронтенда из схемы бэкенда: рассинхрон ломает сборку.
- [x] CI/CD на GitHub Actions: линтеры, типы, тесты, сборка образа с дымовым
      тестом до публикации, релизы. См. [.github/ci.md](.github/ci.md).
- [x] e2e-тесты на Playwright: браузерные сценарии (вход, сотрудники, профиль,
      настройки) против собранного образа, на тех же воротах перед публикацией,
      что и дымовой тест. См. [e2e/README.md](e2e/README.md). Локально в этой
      среде не прогнаны (нет доступа к Docker и запущенному продукту) — первый
      прогон в CI; Playwright разбирает все спеки без ошибок.

## В работе

- [ ] **Кабинет: чего в нём ещё нет.** Смена собственного e-mail невозможна:
      это смена логина, и без подтверждения по почте она превращается в способ
      потерять доступ. Список сотрудников без пагинации: до MVP их десятки.
      Приглашений по ссылке нет — пароль сотруднику задаёт администратор.
- [ ] **Инвалидация сессий.** Смена пароля не отзывает ранее выданные токены:
      с угнанным токеном можно продолжать работать до его истечения.
- [ ] **Воркер фоновых задач.** Таблица очереди и модель есть, планировщик — нет.
- [ ] **Обязательные проверки на `main`.** Правила описаны файлом
      ([.github/rulesets/](.github/rulesets/readme.md)): прямой push запрещён,
      обязательны все пять job'ов CI. К репозиторию они ещё не применены —
      настройки GitHub живут вне кода, и залить их можно только вручную с
      правами администратора: `make protect-main`. До этого CI зелёный, но
      ничего не блокирует — влить красный PR можно без предупреждения.
- [ ] **CI гоняется по два раза на каждый PR.** `test.yml` и `build.yml`
      подписаны и на `push`, и на `pull_request`, а `concurrency` группируется
      по `github.ref` — у этих событий он разный, поэтому взаимно прогоны не
      отменяются. Результат одинаковый, но сборка образа с e2e стоит минут.
      Лечится условием «на push — только для веток без открытого PR» либо
      сужением `push` до `main` и тегов.

- [ ] **Первый релиз.** CI настроен и публикует образ, но тег ещё не выпущен —
      пока в registry пусто. `git tag v0.1.0 && git push origin v0.1.0`.
- [ ] **Helm-чарт** для развёртывания в k3s.
