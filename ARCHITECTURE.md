# Архитектура SalesLift

Этот документ — **оглавление и глоссарий**. Детали живут в `.md` файлах рядом с
кодом; здесь только общая картина и ссылки.

## Структура монорепозитория

```
packages/api    Бэкенд: GraphQL API и фоновый воркер (Python 3.13)
packages/web    Фронтенд: SPA кабинета (TypeScript, React 19)
docs/adr        Значимые решения и их цена
```

Один образ содержит и бэкенд, и собранную SPA: бэкенд раздаёт статику сам.
Поэтому запросы идут с того же origin и CORS не нужен нигде.

## Потоки запросов

### Обычный запрос

```
Браузер
  │  POST /api/v1/graphql, Authorization: Bearer <jwt>
  ▼
GraphQLRouter  (graphql/router.py)
  │  зависимость get_context
  ▼
build_context  (graphql/context.py)
  │  JWT → user_id → SELECT пользователя с его компанией
  │  локаль: профиль → Accept-Language → 'en'
  ▼
Резолвер  (graphql/resolvers/*.py)     ← тонкий адаптер
  │  require_auth / require_permission  ← гард
  ▼
Сервис  (services/**/*_service.py)     ← вся бизнес-логика
  │  явный tenant_id в каждом запросе
  ▼
PostgreSQL
```

**Профиль и права читаются из БД на каждом запросе**, а не берутся из токена.
Цена — один SELECT; выигрыш — изменение прав действует немедленно: разжаловали
администратора, он теряет доступ сразу, а не через неделю, когда протухнет токен.

### Поток ошибок

```
Сервис или гард
  │  raise ValidationError('auth.emailTaken', field='email')   ← ключ i18n, не текст
  ▼
DomainErrorExtension  (graphql/errors.py)   ← расширение схемы, подключено один раз
  │  ключ + локаль → сообщение;  тип ошибки → extensions.code
  ▼
Клиент
  {"errors": [{"message": "Этот e-mail уже зарегистрирован",
               "extensions": {"code": "BAD_USER_INPUT", "field": "email"}}]}
```

Почему расширение схемы, а не `try/except` в каждом резолвере: обёртку можно
забыть, а гарды в неё вообще не попадают — они срабатывают до вызова сервиса.
Первая реализация с ручной обёрткой отдавала клиенту сырой ключ
`auth.unauthenticated` без кода и без перевода. Расширение забыть невозможно.

Сообщения переводит бэкенд, а не фронтенд: только он знает, какая именно
ошибка произошла.

| Класс ошибки          | `extensions.code` |
| --------------------- | ----------------- |
| `NotFoundError`       | `NOT_FOUND`       |
| `ValidationError`     | `BAD_USER_INPUT`  |
| `AuthenticationError` | `UNAUTHENTICATED` |
| `ForbiddenError`      | `FORBIDDEN`       |

`field` заполняется, когда ошибка относится к конкретному инпуту формы.

## Сервисный слой

```
services/
├── permissions.py              единый источник истины: enum разрешений
├── auth/
│   ├── auth_service.py         регистрация компании, вход
│   └── tokens.py               выпуск и проверка JWT
├── users/
│   └── user_roles_permission.py  маппинг ролей → права, гарды резолверов
└── tasks/                      очередь фоновых задач
```

Канонический резолвер:

```python
@strawberry.mutation
async def resolver_auth_login(self, info: Info[Context, None], input: LoginInput) -> AuthPayload:
    """Проверяет учётные данные и выдаёт сессионный токен."""
    ctx = info.context
    result = await auth_service.login(ctx.session, ..., ctx.locale)
    return AuthPayload(token=result.token, user=User.from_model(result.user))
```

Обработки ошибок в резолвере нет намеренно — её делает расширение схемы.

### Сессия передаётся первым аргументом

```python
await auth_service.register(session, data, locale)
```

Отклонение от прототипа, где соединение было модульным глобалом. `AsyncSession`
не безопасна при конкурентном использовании, поэтому глобалом быть не может.
Отвергнута альтернатива `async_scoped_session` с contextvar: прячет сессию,
усложняет тесты и ломается в фоновых задачах, где никакого запроса нет.

Транзакциями управляет **сервис**, а не резолвер: граница транзакции — это
бизнес-решение («компания и её администратор создаются вместе или не создаются
вовсе»), а не деталь транспорта.

### GraphQL-типы объявлены явно, а не выведены из моделей

`graphql/types/user.py` объявляет `@strawberry.type class User` с методом
`from_model()`. Это чуть больше кода, чем автовывод из ORM, но контракт API
перестаёт быть «какие колонки случайно есть у модели»: **`password_hash`
физически не может утечь в ответ, потому что его в типе просто нет**.
Закреплено тестом.

## Multi-tenancy

- Компания (тенант) — корень всех данных. Идентификатор один: `id` (UUID).
- **Поддоменов нет.** Все кабинеты на одном домене.
- **E-mail глобально уникален.** Форма входа — только e-mail и пароль; поиск
  пользователя по e-mail *и есть* резолвинг тенанта. Цена: один человек не
  может работать в двух компаниях под одним адресом. См.
  [ADR-0001](docs/adr/0001-tenant-resolution.md).
- JWT содержит `{user_id, tenant_id}`. `build_context` сверяет `tenant_id` из
  токена с БД — единственная проверка целостности, пережившая отказ от
  поддоменов.

### Изоляция держится на дисциплине, а не на магии

**Каждый метод сервиса принимает `tenant_id` явно; каждый запрос содержит явный
`.where(Model.tenant_id == tenant_id)`.**

Соблазнительно навесить неявный фильтр по `tenant_id` из contextvar, как это
сделано для мягкого удаления. **Нельзя:** фоновые задачи легитимно ходят между
тенантами, и фильтр, который в одном пути кода молча применяется, а в другом
нет, опаснее отсутствия фильтра — он создаёт ложное чувство защищённости.

Единственная гарантия — тесты. У каждого tenant-scoped сервиса **обязателен**
кейс «не видит данные чужого тенанта» (фикстура `other_tenant`).

Postgres RLS — возможный будущий слой усиления поверх этой дисциплины, но не
замена ей.

## Модели данных

```
Tenant (1) ──→ User (many)              permissions: admin | manager | viewer
Tenant (1) ──→ BackgroundTask (many)
```

Все таблицы: UUID PK, `created_at`/`updated_at`, мягкое удаление через
`deleted_at`. Подробности и решения —
[models/readme.md](packages/api/src/saleslift/models/readme.md),
соглашения слоя БД — [db/readme.md](packages/api/src/saleslift/db/readme.md).

Мягкое удаление реализовано глобальным фильтром на `do_orm_execute` — это
единственный паттерн прототипа, у которого в SQLAlchemy нет встроенного
аналога. Он невидим в коде запросов, поэтому описан в
[db/readme.md](packages/api/src/saleslift/db/readme.md).

## Права доступа

`services/permissions.py` — enum без импортов и логики, единственный источник
истины. На фронтенд он попадает **через GraphQL-схему**: регистрируется в
схеме, уезжает в `schema.graphql`, и codegen превращает его в
TypeScript-enum. Отдельной синхронизации файлов нет — рассинхрон невозможен by
construction: удалите право в Python, и codegen упадёт на сборке фронтенда.

`users.permissions` — массив: маркер роли плюс опциональные точечные добавки.
**Порядок значения не несёт**, читать только через `get_effective_permissions()`.

Ритуал добавления права — в
[user_roles_permission.md](packages/api/src/saleslift/services/users/user_roles_permission.md).

## Режимы запуска (APP_MODE)

| Значение | Что делает процесс                          | Где используется          |
| -------- | ------------------------------------------- | ------------------------- |
| `web`    | Обслуживает HTTP, фоновые задачи не гоняет  | Под `api` в k8s           |
| `worker` | Гоняет фоновые задачи, HTTP не слушает      | Под `worker` в k8s        |
| `all`    | И то, и другое в одном процессе             | Разработка, docker compose |

Один образ, разное поведение по переменной окружения.

## Как добавить новую сущность

1. **Модель** — `models/<entity>.py`, унаследовать миксины из `db/base.py`.
2. **Реестр** — добавить импорт в `models/__init__.py` (список явный, без
   автозагрузчика).
3. **Миграция** — `alembic revision --autogenerate`, затем **прочитать глазами**:
   это черновик. Прогнать `upgrade → downgrade → upgrade`.
4. **Сервис** — `services/<domain>/<entity>_service.py`. Сессия первым
   аргументом, `tenant_id` явно, доменные ошибки с ключами i18n.
5. **i18n** — добавить ключи ошибок в `i18n/en.py` и `i18n/ru.py` (тест
   проверит, что наборы совпадают).
6. **Права** — при необходимости новое значение в `services/permissions.py` +
   `USERS_ROLE_MAP`.
7. **GraphQL-тип** — `graphql/types/<entity>.py` с `from_model()`.
8. **Резолвер** — `graphql/resolvers/<domain>.py`, имя `resolver_<домен>_<метод>`,
   гард в первой строке.
9. **Схема** — подключить Query/Mutation в `graphql/schema.py`.
10. **Тесты** — интеграционные на сервис, **включая «не видит чужой тенант»**.
11. **`make codegen`** — схема и типы фронтенда.
12. **Фронтенд** — страница-каталог: `index.tsx` + `queries.ts` + `components/`.
13. **Документация** — `readme.md` рядом с кодом; сюда — только ссылка.

## Глоссарий

| Термин                     | Значение                                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Тенант** (компания)      | Корневая сущность мультитенантной модели. Всё в системе принадлежит ровно одному тенанту. Идентификатор — только UUID. |
| **Сотрудник**              | Пользователь, принадлежащий одному тенанту. E-mail глобально уникален.                                                 |
| **Кабинет**                | Интерфейс компании: сотрудники, настройки, профиль. Живёт на общем домене, без поддомена.                              |
| **Маркер роли**            | Значение `admin`/`manager`/`viewer` в массиве `users.permissions`. Разворачивается в набор прав через `USERS_ROLE_MAP`. |
| **Гранулярное право**      | Значение `Permission_<область>_<действие>`. Проверяется резолвером, гейтит UI.                                         |
| **Эффективные права**      | Плоский список прав после разворачивания роли. Единственный источник для гейтинга UI.                                  |
| **Доменная ошибка**        | Наследник `AppError`: несёт ключ i18n и код, но не текст. Текст подставляется на границе запроса.                      |
| **Мягкое удаление**        | Запись не удаляется, а помечается `deleted_at`. Из выборок исчезает автоматически.                                     |
| **Фоновая задача**         | Строка в `background_tasks`. Таблица одновременно очередь и трекер прогресса.                                          |
| **Воркер**                 | Процесс с `APP_MODE=worker`: разбирает очередь, HTTP не слушает.                                                       |
| **Цепочка кодогенерации**  | `резолверы → schema.graphql → типы фронтенда`. Ломает сборку при рассинхроне.                                          |
| **Прототип**               | `proto-saas/` — предыдущий проект на TypeScript. Источник архитектурных решений. Не часть репозитория, в `.gitignore`. |
